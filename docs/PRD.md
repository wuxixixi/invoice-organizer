# 科研人员发票整理桌面软件 — 产品需求文档（PRD）

## 0. 项目信息

| 项目 | 内容 |
|---|---|
| 文档语言 | 简体中文 |
| 项目名称 | `invoice_organizer` |
| 默认技术栈 | Vite + React + MUI + Tailwind CSS（桌面容器技术选型见「待确认问题」） |
| 产品定位 | 报销前**本地**整理工具：把发票集中放入文件夹，自动识别 / 分类 / 重命名 / 归档并生成整理结果 |
| 文档版本 | v1.0 |
| 作者 | 许清楚（Xu）· 产品经理 |

**原始需求复述**：科研人员把发票集中放入指定文件夹，软件自动识别、分类、重命名、归档并生成整理结果；整理对象、分类字段、命名规则、输出目录、导出模板均需可自定义。用户已明确要求「实现全部核心功能」，因此 P0 与核心 P1 配置能力均在本次范围内。

---

## 1. 产品边界（强制约束，不可越界）

本产品**只做信息提取与整理**，明确不做以下事项：

| 不做 | 说明 |
|---|---|
| 不判断发票真伪 | 仅提取票面信息，不鉴别真伪 |
| 不下审计 / 税务合规结论 | 不提供任何合规性判定 |
| 不认定重复报销 | 仅做文件级去重与同号异件冲突提示，是否重复报销由人判断 |
| 不生成记账凭证 | 输出为台账 / 报告，非会计凭证 |
| 分类标签 ≠ 会计科目 | 自动分类仅为整理标签，不得表述或映射为会计科目 |
| 不宣称适配财政部电子凭证会计数据标准 | 不做此宣称 |

**数据可信原则**：看不清 / 无法提取的字段一律标注「待人工确认」，不臆造；所有字段保留证据与置信状态。

---

## 2. 产品目标

三个正交目标：

| # | 目标 | 衡量方向 |
|---|---|---|
| G1 | **自动化整理**：把科研人员从逐张开票、录入、命名、归档的手工劳动中解放出来 | 人工录入与重命名工作量显著下降；一批文件结束后可直接得到规范归档与台账 |
| G2 | **可控可追溯**：通过「计划预览 → 人工确认 → 执行复核」与本地元数据库，保证结果可解释、可回溯、可回滚，不臆造数据 | 每条归档记录可回溯到来源文件、命中规则、配置版本与批次；未知字段必为「待人工确认」 |
| G3 | **高度可配置**：整理对象 / 分类 / 字段 / 命名 / 目录 / 导出模板均可自定义并版本化，适配不同课题组的整理规范 | 五项配置均可通过 UI 完成；历史批次绑定当时配置版本，配置变更不影响回溯 |

|---|---|---|
| US1 | 科研人员 | 作为科研人员，我希望把一批发票丢进指定文件夹后软件自动识别并整理，这样我不用逐张打开录入和重命名。 |
| US2 | 科研人员 | 作为科研人员，希望在真正归档前看到「旧路径 → 新路径」的候选计划及命中规则，这样我能确认整理结果符合预期再执行。 |

| US4 | 科研人员 | 作为科研人员，希望看不清或字段缺失的发票被标为「待人工确认」而不是被猜填，这样我不会因错误数据而在报销环节受阻。 |

| US9 | 科研人员 | 作为科研人员，希望整理失败时已成功的项被保留、失败项可单独重试，这样我不必从头重跑整个批次。 |

## 4. 需求池（P0 / P1 / P2）

> P0 = 必须有（最小闭环）；P1 = 应该有（可配置治理，核心项本次实现）；P2 = 可以有（集成扩展）。

### 4.1 P0 — 最小闭环（本次必须实现）

| ID | 需求 | 验收判据 |
|---|---|---|
| P0-01 | 输入目录监控与写稳检测 | 配置 watch 路径 / 递归 / 写稳秒数；文件大小 + mtime 两轮一致且无共享写句柄后才入队；写稳前不解析 |
| P0-02 | 文件入队与 SHA-256 去重 | 每个文件计算 SHA-256；同哈希文件不重复入队；哈希写入元数据 |
| P0-03 | 解析 / OCR 适配器（受限进程、可替换） | OCR 在受限子进程中运行、超时可终止；适配器接口可替换；单票 OCR 超时经有限重试后转「待处理」 |
| P0-04 | 八字段提取 | 提取票号 / 开票日期 / 购买方名称及信用代码 / 销售方名称及信用代码 / 项目名称 / 金额；每字段带证据与置信状态；无法提取标「待人工确认」，不臆造 |
| P0-05 | 金额与日期规范 | 金额以整数分存储，默认取票面「合计」（不含税），仅显式配置才取「价税合计」；日期统一 YYYY-MM-DD |
| P0-06 | 票据聚合 | 按票号聚合附件，一票一记录；多行项目合并为一条记录；同票号不同哈希进入冲突复核 |
| P0-07 | 规则引擎（分类 / 命名 / 目录） | 按配置计算分类标签与目录 / 文件名候选；命中规则可见；未命中归入「未分类 / 待人工确认」 |
| P0-08 | 计划预览与人工确认 | 预览展示旧→新路径、命中规则、冲突、缺字段；`previewRequired=true` 时未确认不得写归档副本 |
| P0-09 | 归档执行器 | 原件只读、不自动删除；仅写归档副本；原子重命名、不覆盖重名（追加序号或隔离）；写后 SHA-256 复核一致；失败可回滚并记日志 |
| P0-10 | 本地元数据库 | 记录文件哈希、字段证据、批次、计划、归档结果、冲突与复核状态；本地存储，默认离线 |
| P0-11 | 导出台账 | 导出 Excel / CSV 台账，列序与金额展示符合规格（见 5.5）；导出数据可回溯批次与配置版本 |
| P0-12 | 异常矩阵核心项 | 模糊遮挡→待人工确认；同号异件→冲突复核；软链接 / 绝对路径注入 / `..`→规范化真实路径并拒绝；目录无权限 / 磁盘满→批次暂停保留成功项 |

### 4.2 P1 — 可配置治理（核心项本次实现）

| ID | 需求 | 验收判据 |
|---|---|---|
| P1-01 | 五项自定义 UI | 整理对象 / 分类字段 / 命名规则 / 输出目录 / 导出模板均可在 UI 配置并校验；输入与输出目录不得互相包含，冲突时拒绝保存 |
| P1-02 | 配置版本化 | profileId 带版本；每次变更生成新版本；历史批次绑定当时版本，配置变更不影响既有批次回溯 |
| P1-03 | 批次回溯 | 可按批次 ID 查看当时配置、输入文件、计划、归档结果、冲突与复核记录 |
| P1-04 | 权限与审计 | 本地操作（配置变更 / 确认 / 执行 / 导出 / 回滚）记录审计日志（时间、操作、对象、结果）；关键操作要求本地授权 |
| P1-05 | 备份与恢复 | 可备份元数据库与配置；可从备份恢复到指定批次 / 版本状态 |
| P1-06 | 批次报告与待复核清单导出 | 导出批次报告与待复核清单，字段与格式符合 5.5；可回溯来源与依据 |

### 4.3 P2 — 集成扩展（本次不实现，留存接口）

| ID | 需求 | 验收判据 |
|---|---|---|
| P2-01 | 更多票种支持 | 通过适配器扩展票种，不改动核心解析逻辑即可接入 |
| P2-02 | 插件 / 适配器扩展 | 提供插件接口，支持第三方分类 / 命名 / OCR 插件 |
| P2-03 | 财务系统对接 | 预留导出 / 接口扩展点；本 PRD 不含具体对接实现 |

## 5. 关键功能规格

### 5.1 字段规则（八字段槽位）

| 字段 | 槽位键 | 规则 |
|---|---|---|
| 票号 | `invoiceNo` | 主键聚合依据；缺失 / 不可辨认为「待人工确认」 |
| 开票日期 | `issueDate` | 统一 YYYY-MM-DD；多种票面格式归一 |
| 购买方名称 | `buyerName` | 原样提取，保留证据 |
| 购买方统一社会信用代码 | `buyerTaxId` | 提取并做长度 / 字符集校验，异常标「待人工确认」 |
| 销售方名称 | `sellerName` | 原样提取，保留证据 |
| 销售方统一社会信用代码 | `sellerTaxId` | 同上 |
| 项目名称 | `itemName` | 多行项目合并为一条记录 |
| 金额 | `amountCent` | 整数分存储；默认取「合计」（不含税），显式配置才取「价税合计」 |

字段通用规则：

| 项 | 规则 |
|---|---|
| 置信状态 | 每字段为三类之一：高置信 / 低置信 / 待人工确认；低置信与待确认均需人工复核 |
| 证据 | 每字段记录来源文件、页码、区域坐标或原文片段 |
| 不臆造 | 无法确认即留空并标「待人工确认」，禁止推测填充 |
| 展示 | 金额以元展示（内部仍为整数分）；用户提供值亦按分存储 |

### 5.2 分类规则

- 配置结构：`categories: [{ id, label, priority, match }]`。
- 按 `priority` 从小到大依次匹配，命中首条即停止；可配置「命中全部」策略。
- `match` 可对白名单字段做关键词 / 正则 / 等值匹配。
- 未命中归入「未分类 / 待人工确认」。
- **分类标签仅为整理标签，不得表述或映射为会计科目**（产品边界）。

### 5.3 命名模板语法

- 配置：`directoryTemplate`（相对归档根目录）与 `filenameTemplate`。
- 占位符语法：`{字段键}`，如 `{issueDate}` `{sellerName}` `{amountCent}` `{invoiceNo}`；仅允许八字段白名单及少量安全元变量（如批次号）。
- 安全约束：

| 约束 | 规则 |
|---|---|
| 白名单 | 仅白名单占位符可被解析，其他一律忽略并告警 |
| 禁止脚本 | 模板不执行任何脚本 / 表达式，纯字符串替换 |
| 路径安全 | 过滤路径分隔符注入、`..`、绝对路径、保留字符；输出前规范化并校验真实路径必须位于归档根目录内 |
| 字符清洗 | 非法字符替换为安全字符或下划线；长度截断；空占位符回退为「待人工确认」 |
| 重名处理 | 目标已存在时不覆盖，追加序号（如 `_2`）或进入隔离区 |

- 示例：`{issueDate}_{sellerName}_{amountCent}_{invoiceNo}`

### 5.4 去重规则

| 情形 | 处理 |
|---|---|
| 同票号 + 同 SHA-256 | 判定为重复文件，跳过或进入隔离区，不重复归档 |
| 同票号 + 不同 SHA-256 | 进入冲突复核，人工判断，不自动取舍 |
| 不同票号 + 同 SHA-256 | 按哈希去重（同一物理文件），保留一条记录并关联多票号 |
| 一 PDF 多票 | 拆分为多条记录，保留同源标记（来源文件 + 页码 / 区域） |
| 重名文件 | 不覆盖，按 5.3 追加序号或隔离 |

### 5.5 导出规格

| 输出物 | 内容 | 规格 |
|---|---|---|
| 台账（Excel / CSV） | 八字段 + 分类标签 + 归档路径 + 批次 ID + 配置版本 + 字段状态 | 列序可配置；CSV 编码可配置（默认 UTF-8 BOM 兼容 Excel）；金额以元展示、内部整数分 |
| 批次报告 | 批次汇总：输入数 / 成功 / 失败 / 冲突 / 待复核、配置版本、时间范围、异常摘要 | 每条含来源与依据，可回溯 |
| 待复核清单 | 待人工确认 / 低置信 / 冲突条目，含原因与定位 | 支持人工回填后重新执行 |

模板映射仅允许白名单字段，与命名模板同样禁止脚本执行。

## 6. 配置模型（参考）

```json
{
  "profileId": "default",
  "version": 3,
  "watch": { "path": "D:/inbox", "recursive": true, "settleSeconds": 3 },
  "output": { "archiveRoot": "D:/archive", "quarantine": "D:/quarantine" },
  "organizeBy": "invoiceNo",
  "categories": [
    { "id": "travel", "label": "差旅", "priority": 10, "match": { "field": "itemName", "contains": "交通" } }
  ],
  "fields": ["invoiceNo", "issueDate", "buyerName", "buyerTaxId", "sellerName", "sellerTaxId", "itemName", "amountCent"],
  "amountSource": "totalExclTax",
  "directoryTemplate": "{issueDate}/{sellerName}",
  "filenameTemplate": "{issueDate}_{sellerName}_{amountCent}_{invoiceNo}",
  "export": { "template": "default", "columns": ["invoiceNo", "issueDate", "sellerName", "amountCent"], "encoding": "UTF-8-BOM" },
  "execution": { "previewRequired": true, "preserveSource": true, "dedupe": true }
}
```

**规则**：`amountSource` 取 `totalExclTax`（默认，合计不含税）或 `totalInclTax`（价税合计，需显式配置）；历史批次绑定配置版本；输入与输出目录不得互相包含。

## 7. 异常矩阵

| 异常 | 处理策略 |
|---|---|
| 模糊 / 印章遮挡 | 相关字段标「待人工确认」，不臆造，进入待复核 |
| 同票号不同哈希 | 冲突复核，人工判断 |
| 一 PDF 多票 | 拆分并保留同源标记 |
| 目录无权限 / 磁盘满 | 批次暂停，保留已完成项，失败项可重试 |
| OCR 超时 | 有限重试后转「待处理」，不无限等待 |
| 软链接 / 绝对路径注入 / `..` | 规范化真实路径并拒绝越界写入 |
| 写稳检测 | 文件大小 + mtime 两轮一致 + 无共享写句柄 |
| 写入失败 | 原子重命名 + 失败回滚 + 日志记录 |

## 8. 非功能需求

### 8.1 隐私与安全

| 项 | 需求 |
|---|---|
| 本地优先 | 默认离线运行；无用户显式授权不得上传任何数据 / 字段 / 图像 |
| 原件只读 | 源发票只读，不修改、不自动删除；仅生成归档副本 |
| 权限与审计 | 关键操作需本地授权；配置变更 / 确认 / 执行 / 导出 / 回滚全程审计日志 |
| 模板安全 | 命名 / 导出模板仅白名单字段、纯字符串替换、禁止脚本执行 |
| 路径安全 | 真实路径规范化校验，拒绝软链接 / 绝对路径注入 / `..` 越界 |
| 副本完整性 | 归档副本写后 SHA-256 复核，不覆盖重名 |

### 8.2 性能

| 项 | 需求 |
|---|---|
| 写稳检测 | 两轮采样（大小 + mtime）间隔按 `settleSeconds` 配置；避免过早解析 |
| OCR 健壮性 | 受限进程，单票超时有限重试（次数与阈值见待确认问题），超时转「待处理」不阻塞批次 |
| 批处理稳定性 | 个别异常不导致整体失败；成功项保留，失败项可单独重试 |
| 大文件 / 多页 | 解析大 PDF / 多页时内存受控，受限进程防止拖垮主程序 |

### 8.3 兼容性

| 项 | 需求 |
|---|---|
| 操作系统 | Windows 桌面（具体版本见待确认问题） |
| 输入格式 | 常见票种 PDF 与图片（JPG / PNG 等），扫描件 / 电子票版式差异通过黄金样本覆盖 |
| 输出格式 | Excel / CSV（UTF-8 BOM 默认，兼容 Excel 中文不乱码） |
| 编码与日期 | 日期 YYYY-MM-DD；金额整数分存储、元展示 |

## 9. 验收原则

- 使用**脱敏黄金样本集**覆盖：版式差异、印章遮挡、扫描倾斜、同号异件、重名、金额差异、异常断点。
- 样例需人工标注期望结果（含「待人工确认」项）作为比对基准。
- **不编造任何准确率 / 性能承诺数值**；相关指标在待确认问题中给出量化目标建议后由团队确认。

## 10. 待确认问题

| # | 问题 | 影响 | 建议默认 |
|---|---|---|---|
| Q1 | 桌面容器技术选型（Electron / Tauri / .NET WPF） | 决定打包、本地文件访问与 OCR 进程隔离实现 | 若沿用 Web 栈默认 Electron，需评估包体与权限模型 |
